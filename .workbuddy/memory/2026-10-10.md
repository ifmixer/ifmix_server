## 三个生产问题（同一轮）

### 1. Hikari `Failed to validate connection … closed` — 根因查明，**生产已处置**

**unattended-upgrades 每天 ~06:17 UTC 自动更新 → 升级 libxml2/libpng → needrestart 自动重启 postgresql**。
证据链：unattended log 06:17:02 启动 / 06:17:05 列出 `libpng16-16t64 libxml2-16` → PG log 06:17:09
`received fast shutdown request` + 10 条 `terminating connection due to administrator command`
→ 0.2s 后 ready → 06:17:13~06:18:51 十条 PoolBase WARN。PG 日志显示历史上 09-19/20/21/26/30、10-03/09
同样发生过（每 3-7 天）。已排除 idle_session_timeout（0）与 OOM。
**坑**：`systemctl show postgresql -p ExecMainStartTimestamp` 显示 9-25 起未重启——needrestart 不走 systemctl，
查 PG 重启唯一可靠来源是 PG 自己的日志。

用户拍板「禁用所有自动更新」，已执行（备份 `/var/backups/ifmix/20auto-upgrades.bak.20261010`）：

- `/etc/apt/apt.conf.d/20auto-upgrades` 两项 `"0"`；`apt-daily.timer` / `apt-daily-upgrade.timer` /
  `unattended-upgrades.service` **disable --now + mask**（mask 防包升级重新 enable）；`fwupd-refresh.timer` disable。
- `/etc/needrestart/conf.d/ifmix-stateful-services.conf`：用 **`override_rc`**（按 unit 名匹配，值 0 = 只打印提示不重启）
  而不是 `blacklist`（按可执行文件路径匹配 + 完全忽略）：`qr(^postgresql)` / `qr(^redis-server)` => 0。
  校验（57 rules, pg=0）用 perl 加载主配置 + conf.d 后打印 keys。
- snap：无 systemd timer，由 snapd 内部调度 → `snap set system refresh.hold`（上限 90 天，2027-01-08 到期**需续期**）。
  保留 amazon-ssm-agent（AWS 运维通道）。
- **坑**：apt 配置备份不能放 `/etc/apt/apt.conf.d/`（扩展名不合法 → 每次 apt 都吐 `N: Ignoring file …`）。
- 未做：`ClusterRegistry` 的 `max-lifetime`/`keepalive-time`——根因已在上游消除，留作可选优化。
- 副作用：CVE 补丁需手动，建议每月维护窗口 `apt update && apt upgrade -y` + `needrestart -r a`。

### 2. agnes-3.0-flash 图片拉取失败 → 已修（SpringAiScanRunner）

provider 回源下载图片超时，被 provider 自己报成 **400**（msg 含 `loading IMAGE data … Timed out while downloading media URL`）。
原来 `isNonRetryableRequestError` 把 400/422 一律当不可重试 → 直接失败。
加 `isTransientImageFetchFailure`（先要求类型化 400/422，再要求命中图片短语）+ 换 key 重试上界 2，
**不冷却不禁用 key**；耗尽才抛 `INVALID_REQUEST`「AI could not load the image (upstream fetch failed)」。
图片 URL 是公开桶直拼（`getPublicUrl`，非 presigned、无 expiry）→ 重试安全。
注：`ScanDto` 里 imageUrl 的注释「预签名下载 URL」是过时注释（实际是公开 URL）。
