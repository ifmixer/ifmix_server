## 修复 v1.0.7 测试问题（commit 0c693d6a）

用户跑全量测试暴露两个问题，均已修复并提交（feature/v1.0.7）：

1. **ScratchRowLockProbeTest 编译失败**：漏 `import java.util.Collections`，`sqls` 变错误类型后连锁引发 4 处报错（74/75 行 `it`、107 行类型推断）。补 import 即消。
2. **AiConfigDisableKeyDbTest 5 用例失败**：本机 Docker 未运行，Testcontainers 起不了容器。根因是测试设计缺陷——`private val config = AiConfig(sqlClient, mock())` 在**构造阶段**触发 `sqlClient` 懒加载，`@BeforeEach` 的 `assumeTrue` 跳过来不及执行。改为 `by lazy` 后无 Docker 时干净跳过（与 CustomerScanMetricsRepositoryDbTest 模式对齐）。此隐患 v1.0.6 就存在，只是以前跑测试时 Docker 可用。

修复后：core-api 446 用例 0 失败（11 跳过，均为无 Docker 的 DB 用例），core-job 全过。
